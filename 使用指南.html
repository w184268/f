WatchTube 使用指南

孩子在手表上问一句，自动收到一段讲这件事的科普视频。这份指南按「照着点」的方式写，不需要编程基础。

孩子在手表上说话/打字 　↓ 小天才 App 弹出通知 手机上的桥接程序 （本指南要装的东西） 　↓ 通过局域网发给服务端 服务端：理解问题 → 搜 B站 → 安全过滤 → 剪前 60 秒 → 压成 3MB 　↓ 手机取回视频 → 写进相册 → 自动/一键发回微聊 　↓ 🎉 孩子抬起手腕就能看了

先搞清楚：这套东西是两个部分

必须同时具备，缺一不可：

部分跑在哪干什么
服务端（大脑）你家的电脑 / 小主机 / NAS理解问题、搜视频、压制
手机端（手脚）你的安卓手机抓孩子的消息、把视频发回手表
服务端那台电脑要开着，一般用家里的台式机或常年不关的小主机就行。

三选一：你的情况适合哪条路

推荐 · 不用装任何软件

A. GitHub 网页自动编 APK

把项目传到 GitHub，它自带的构建机帮你编译成 APK，直接下载。全程网页操作，约 10 分钟。

有电脑当选

B. 用 Android Studio 编译

装 Development 环境（约 1GB），然后点一下运行就装到手机。适合以后想自己改代码。

只有手机 · 半自动

C. 用 Tasker 免安装 APK

装个 Tasker 配几条规则即可，但最后一步要手动点几下发送。

第一部分：让服务端先跑起来

不管选哪条手机路线，这部分都要做。

第 1 步：装两个东西

  • Python 3.10+：python.org 下载安装，装的时候务必勾选 "Add Python to PATH"
  • ffmpeg：负责压制视频
    • Windows：去 gyan.dev/ffmpeg/builds 下载 essentials 版，解压后把里面的 bin 文件夹路径加到系统 PATH
    • Mac：brew install ffmpeg
    • Ubuntu：sudo apt install ffmpeg

验证装好没：终端里输入 ffmpeg -version，出版本号就成。

第 2 步：改配置

1 进入项目里的 server 文件夹，把 config.example.yaml 复制一份，改名 config.yaml
2 用记事本/VS Code 打开 config.yaml，改这两处： 
server:
  public_base_url: "http://192.168.1.10:8787"   ← 改成你自己电脑的局域网IP
  bridge_key: "自己起一串密码"                   ← 手机App里要填一样的

understanding:
  api_key: "sk-xxxx"                            ← 留空也能跑（会自动降级）
3 查自己电脑的局域网 IP：
  • Windows：打开命令提示符，输入 ipconfig，找「IPv4 地址」
  • Mac/Linux：终端输入 ip addr 或 ifconfig

第 3 步：启动

Windows 双击 run.bat；Mac/Linux 终端执行 ./run.sh。

看到 "WatchTube 已启动" 就成了。浏览器打开 http://你的IP:8787 是家长看板——孩子问了什么、选了哪条视频、里面的处理日志，全在这。

第 4 步：不用手机，先自测一遍

python3 ../tools/selftest.py "恐龙为什么会灭绝啊"

看到「🎉 全链路跑通」说明服务端这边的活已经能干了。

第二部分：手机端

路线 A · GitHub 网页编 APK（推荐）

原理：GitHub 免费提供云端编译机，你把代码传上去，它帮你编好 APK 让你下载。

先解决一件事：文件夹怎么传上去？

GitHub 网页只能拖拽文件夹，点「choose your files」是选不了文件夹的（那是单文件选择器）。所以按你的情况挑一种：

最稳 · 推荐

① 拖文件夹进网页

Chrome 或 Edge 打开仓库 → Add file ▾ → Upload files → 把 watchtube 整个文件夹按住拖到虚线框里 → 松手，底部填说明 → Commit changes。

更傻瓜

② 装 GitHub Desktop

下载 desktop.github.com 装上并登录 → File → Add local repository 选 watchtube 文件夹 → 提示要不要建仓库就点是 → 右上角 Publish repository，名字填仓库名、勾掉 Keep this code private → 发布。

命令行

③ 跑一条脚本

不想点来点去就双击 tools\push_github.bat（Windows）或执行 bash tools/push_github.sh，把仓库地址当参数带上。

⚠️ 上传后务必检查一件事：仓库文件列表里点开 .github/workflows/build-apk.yml 看在不在。这个隐藏目录偶尔会被浏览器跳过，它没了 Actions 就不会触发。
没有 → 换方案 ② 或 ③ 重传一遍。

如果上传时提示「此文件是隐藏的」

GitHub 网页上传会拒绝以 . 开头的隐藏文件和目录 —— .github、.gitignore 都属此类。不用重传全部文件，其他文件都已经在仓库里了，只要单独补建一个工作流文件：

1 仓库首页 → Add file ▾ → 这次选 Create new file（不是 Upload files）
2 顶部那个文件名输入框里，手动敲完整路径：.github/workflows/build-apk.yml
框里默认是灰字提示，直接输入上面这串（含两个目录层），GitHub 会自动把目录建出来 —— 走"新建文件"这条路不受隐藏文件限制。
3 把下面这段原样粘进页面的大文本框里（点代码块右上角的「复制」按钮）： 
name: 构建 APK

on:
  push:
    branches: [ main, master ]
  # 允许在 Actions 页面手动点一下重新构建，不用推代码
  workflow_dispatch:

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: 检出代码
        uses: actions/checkout@v4

      - name: 安装 JDK 17
        uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: 'temurin'

      # GitHub 的构建机自带 ANDROID_HOME 和 sdkmanager。
      # 这里补齐许可与目标 SDK；加 || true 是为了避免个别镜像路径不同把流程卡死
      # —— 只要许可已接受，Gradle / AGP 会自动安装缺失的 SDK 组件。
      - name: 接受 SDK 许可并安装构建工具
        run: |
          set +e
          yes | sdkmanager --licenses > /dev/null 2>&1
          sdkmanager --install "platforms;android-34" "build-tools;34.0.0" > /dev/null 2>&1
          if [ -d "$ANDROID_HOME/cmdline-tools/latest/bin" ]; then
            yes | "$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" --licenses > /dev/null 2>&1
            "$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" --install "platforms;android-34" "build-tools;34.0.0" > /dev/null 2>&1
          fi
          echo "ANDROID_HOME=$ANDROID_HOME"
          ls "$ANDROID_HOME" || true
          exit 0

      - name: 安装 Gradle 8.7
        run: |
          set -e
          curl -fsSL -o /tmp/gradle.zip https://services.gradle.org/distributions/gradle-8.7-bin.zip
          unzip -q /tmp/gradle.zip -d /opt
          echo "/opt/gradle-8.7/bin" >> "$GITHUB_PATH"
          /opt/gradle-8.7/bin/gradle --version | head -5

      - name: 缓存 Gradle 依赖
        uses: actions/cache@v4
        with:
          path: |
            ~/.gradle/caches
            ~/.gradle/wrapper
          key: gradle-${{ runner.os }}-${{ hashFiles('android/**/*.gradle.kts', 'android/gradle/wrapper/gradle-wrapper.properties') }}
          restore-keys: gradle-${{ runner.os }}-

      - name: 编译 Debug APK
        run: gradle assembleDebug --no-daemon --stacktrace
        working-directory: android

      - name: 核对产物
        run: ls -lh android/app/build/outputs/apk/debug/
        working-directory: ${{ github.workspace }}/

      - name: 上传 APK 成品
        uses: actions/upload-artifact@v4
        with:
          name: watchbridge-debug-apk
          path: android/app/build/outputs/apk/debug/*.apk
          retention-days: 30
4 拉到底点 Commit changes，再去 Actions 页面，构建就会自己开始
💡 .gitignore 同样传不上去，但它只影响你本地 git 的行为，不影响编译，可以不补。
真想要的话，用同样办法在文件名框输入 .gitignore 建一个即可。
1 打开 github.com 注册/登录（免费的），点右上角 + → New repository
2 仓库名随便填（比如 watchtube），选 Public（公开仓库的构建额度完全免费），勾选 Add a README，点创建
3 仓库建好后停在首页，用上面三种办法之一把 watchtube 整个文件夹传进来（推荐直接拖进去）
4 点页面上方的 Actions 标签：左边列表里应该有「构建 APK」，右边是它的运行记录，第一条带 🟡 黄圈正在跑 —— 什么都不用点，等 5–10 分钟
⚠️ 如果进来看到的是「欢迎使用 GitHub Actions」的引导页，说明 .github 没传上来 —— 别在那一页选模板，回头换 GitHub Desktop 或脚本重传一次。
引导页下方的 skip this and set up an existing workflow yourself 是给「自己手写工作流」用的，你已经有工作流了，不需要。

看到「Workflows aren't being run on this repository」怎么办

完整提示一般是这样：
Workflows aren't being run on this repository
GitHub Actions is not currently enabled on this repository.

这不是你的工作流写错了 —— 是仓库层面还没打开 Actions 开关。新仓库默认可以是关闭状态。
1 仓库页面最上面那排标签，点 Settings（最右边，齿轮图标）
2 左侧栏往下拉，找到 Actions → 点 General
注意：是左侧栏的 Actions，不是顶部标签那个 Actions。路径是 Settings → Actions → General。
3 页面往下滚到 Actions permissions 这一段，选中 Allow all actions and reusable workflows（允许所有操作）
4 页面最下面点绿色的 Save 保存
5 回到顶部 Actions 标签，现在左边就能看到「构建 APK」了。若还没跑，按下面「手动开一下」点一次 Run workflow
💡 还有两种少见情况：
① 企业/学校账号：组织可能被管理员统一禁用了 Actions，Settings 里找不到开关，只能找管理员开。
② 只看到 Workspace 模板页：说明 .github/workflows/ 里真的没文件，回去按上一节「此文件是隐藏的」补建。

没自动跑？手动开一下

1 在 Actions 页面左侧列表点「构建 APK」这一项（不是点右边那条运行记录）
2 右侧顶部会出现一条浅蓝提示条，右边有个灰色的 Run workflow ▾ 按钮，点它
3 弹窗里 Use workflow from 下拉选 Branch: main（必须选对，选别的分支没有工作流），右边绿色的 Run workflow 点下去
4 页面刷新，上面多一条正在转圈的记录，点进去可以看实时日志

怎么知道成没成

你看到的意思 / 怎么办
🟡 黄圈在转正在编，别急，第一次要拉一堆依赖

💡 顺手说一句：这个工作流设的是「有 push 就跑」，所以哪怕你只改了 server/ 或文档，Actions 也会重编一遍 —— 无害，就是白等几分钟。
想省时间，commit 消息里带上 [skip ci]，比如 改了点配置 [skip ci]，就不会触发。
5 变绿打勾 ✅ 后点进去，拉到页面底部 Artifacts 区，点 watchbridge-debug-apk 下载
6 解压 zip，得到 app-debug.apk，传到手机安装（微信/QQ 传给自己，或用数据线）
⚠️ 如果你已经把填了真实密码的 config.yaml 传上去了 —— 公开仓库里别放真实密码，APK 里不含它，不影响使用，但建议把 server/config.yaml 删掉再传。
💡 这一步我无法替你实跑（沙箱里连不上 Google 的 SDK 下载站），所以万一 Actions 报红：把报错信息发我，我来改。这是很标准的构建流程，成功率很高。

路线 B · 用 Android Studio 编译（电脑软件，最直观）

这条路线现在很推荐。项目已经改成零第三方依赖，Android Studio 第一次同步只要拉 AGP + Kotlin 两个插件， 不需要再下 20 多个 androidx 库 —— 国内网络也能顺利跑通。
1 下载安装 Android Studio：developer.android.com/studio（约 1GB，一路下一步；装完首启会给一个 Setup Wizard，选 Standard 即可，它会顺手把 SDK 装好）
2 启动后选 Open（不是 New Project），目录选中项目里的 android 文件夹 —— 注意是 android 这一层，不是最外层的 watchtube
3 右下角弹 Trust Project 就点同意；然后等右下角进度条跑完（同步 Gradle）。零依赖的情况下大约 2–5 分钟
⚠️ 如果同步报 Failed to resolve: com.android.tools.build:gradle 之类的下载失败 —— 网络问题。项目里已经预置了阿里云镜像，一般不会遇到； 真遇到就检查是否开了全局代理（关掉再试），或点 File → Invalidate Caches / Restart。
4 手机：设置 → 关于手机 → 连点"版本号"7 次 打开开发者模式 → 返回 → 开发者选项里开 USB 调试
5 数据线连电脑，手机上允许 USB 调试。屏幕右上角设备列表里会出现你的手机
6 点绿色三角 ▶️ 运行，手机会自动装上 WatchBridge

路线 C · Tasker 免 APK（最后一步手动）

适合：不想折腾编译，愿意每次手动发出去。

1 手机装 Tasker + AutoNotification 两个 App
2 Tasker 里新建 Profile：Event → Plugin → AutoNotification → Intercept，Apps 选小天才，勾选 Include Notification Text
3 关联任务里加 HTTP Request 动作： 
Method:  POST
URL:     http://你的电脑IP:8787/api/v1/ingest
Headers: Content-Type:application/json
Body:    {"sender":"孩子","text":"%antext"}
4 再建一个定时 Profile（每 2 分钟），用 HTTP Request 取件：http://你的IP:8787/api/v1/outbox，把返回的 video_url 下载下来存到相册
5 收到通知后手动操作：打开小天才 App → 微聊 → 发送相册里刚下载的视频

第三部分：装完 App 后配置四件事

1 打开 WatchBridge，填服务端地址（http://你的电脑IP:8787）和API Key（你在 config.yaml 里写的那个），点保存
2 点 测试连接，看到「连通正常」就是通了 —— 通不了的话检查两端是不是在同一个 WiFi
3 点 开启消息监听权限，在系统设置里勾选 WatchBridge
点 加入电池优化白名单（不加的话半夜会被系统杀掉）
4 想要全自动的话，点 开启无障碍，找到「手表视频投递」打开
建议先开着「干跑模式」跑一次：它会把小天才界面上的按钮全部记到日志里但不真点，对着日志把发送脚本调准，再关掉干跑。

验收：让孩子问一句试试

让孩子在手表上说「为什么天是蓝色的」，30 秒左右：

  1. App 日志里应看到「捕获消息」→「已提交服务端」
  2. 大约 40 秒后看到「下载完成」→「投递完成」
  3. 孩子手表上收到一段 60 秒的视频
  4. 家长看板同步显示这条记录

常见问题

症状大概率原因
孩子发消息，服务端毫无反应通知监听没授权；或同一句话 8 秒内重复被去重了
App 一直显示"取件失败"public_base_url 填错了；手机和电脑不在同一网络
服务端报编码器错误ffmpeg 没装好，或版本太老
自动发送点了乱七八糟的地方脚本按钮对不上，开干跑模式看日志调
隔天不工作了被省电策略杀了，加白名单（各路径见 README）
孩子收不到视频你的手表型号不支持微聊视频 —— 先用手在小天才 App 里给孩子发个视频试试。
不行就把 reply_mode 改成 audio（语音讲解）
🎯 一句话总结：服务端跑在家里电脑（自测脚本验证通过即可），手机上用 GitHub 编出来的 APK 装上授权， 然后让孩子在手表上问一个问题试试。有报错随时把日志贴出来。
